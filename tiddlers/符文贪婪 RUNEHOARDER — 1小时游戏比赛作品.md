**工作区**：`D:\work\web\rouge`

## 融合目标

土豆兄弟（类幸存者刷怪循环）× 海克斯大乱斗（符文 + 羁绊），差异化支点是**经济体系**与**锻体碎片**。

| 层 | 来源 | 特点 |

统一在 `enemy.st` 上：灼烧 / 感电（含弹射）/ 冰缓 / 麻痹 / 猎物印记。伤害入口 `SYS.damage` 集中处理易伤、破冰增伤、处决阈值、暴击与麻痹。

## 排期教训（可复用）

1. **无头冒烟测试是核心投资**。`test/smoke.js` 用最小 DOM/Canvas 桩驱动真实逻辑，10 分钟内抓出 4 个致命缺陷：`spawnAt` 未导出、参数名遮蔽工具函数、符文按 id 索引用对象下标（返回 undefined）、`Digit1` 与 `Digit` 键码不一致导致升级面板永久卡死。
2. **O(n²) 是隐形杀手**。敌人分离最初写成全量两两比较，140 个敌人时无头测试跑超 8 分钟。改为网格 3×3 邻域后瞬间完成。浏览器里同样会掉帧。
3. **DOM id 必须与 JS 键名严格一致**。`ovTitle` vs `ov-title` 的不一致导致所有覆盖层开关静默失效——页面能跑、游戏在跑，只是关不掉标题页。已统一为 DOM 原名。
4. **属性真值字符串陷阱**。`setAttribute('data-open','0')` 仍会被 `[data-open]` 选择器命中。改为开启时设值、关闭时 `removeAttribute`。

## 脚底圆环跑到头上的 bug

`blit()` 的水平翻转分支里目标矩形写的是 `-h + h`，等于 0：

```javascript
if (flip) { ctx.translate(x, y); ctx.scale(-1, 1);
  ctx.drawImage(img, 0,0,w,h, 0, -h + h, w, h); }   // ← 错
else ctx.drawImage(img, x - w/2, y - h, w, h);      // ← 对
```

非翻转分支把精灵底边对齐到 y（脚底），翻转分支把顶边对齐到 y，精灵整体下移一个身位。角色朝左时精灵掉到脚下，留在原地的阴影椭圆与大招就绪环就升到了头部高度。改为 `w/2, -h`。

规律：**镜像绘制时目标矩形的 x 也要跟着翻转**，不能照抄非翻转分支的 `-w/2`。

## 性能：地板 drawImage 热点

美术升级时把地板改成双层阴影 + 接缝纹理，冒烟测试直接跑超 5 分钟。新写 `test/perf.js`（Proxy 桩统计 canvas 调用次数）定位：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| drawImage / 帧 | 571 | 21 |
| 帧内 canvas 调用 | ~2700 | ~230 |

地板原本每帧用 900 次 drawImage 拼 16×16 瓦片。改为启动时把整块地面烘焙成一张 `CFG.W × CFG.H` 的图，运行时 1 次 drawImage。

顺带把 `enemyArt` / `heroArt` 按 kind 缓存精灵引用，消除渲染循环里的正则匹配与字符串拼接；阴影改为实体排序后统一先画一层，避免逐个调用。

**教训**：给 canvas 做美术增强时，每新增一层就要想清楚它是「烘焙一次」还是「每帧 N 次」。纯装饰性的静态图案一律烘焙。
